Design convergence · Wave 3 · mockup for approval

Lighting becomes a sheet

The fixture table is the last surface in the application that is a form pretending to be a list. Twenty-four live controls, thirteen columns, and no read state at all — a rig of two hundred fixtures cannot be scanned, only filled in. This is what it becomes, drawn entirely in bricks the audio tabs already ship.

01 · what is there now

Thirteen columns, and every cell is a control

Below is today's Lighting tab, reproduced at its real sizes. It is a navigation-tier ui/Table — px-3 py-3 rows, text-sm, zebra striping — with an Input or a Select in almost every cell, persisting on blur.

The zebra striping is the tell. At six rows it is tidy; at two hundred it is banding. And because there is no read state, the eye has to parse a border and a background before it reaches a number, on every cell, in every row.

02 · what it becomes

One panel, nine columns, nothing to parse but the data

The same rig, as the work panel every dense tab converges on: a bar, a sheet, and a strip that closes it from inside. Clicking a row opens its editor directly beneath. Nothing in a row is a form control.

Row height goes from about 90 px to 25 px, so a screen shows roughly twenty-eight fixtures instead of seven. That is the whole argument — a rig is a thing you read down, and until now you could not.

03 · the strip

Three answers to “does the plan hold?”

The strip is the one genuinely new capability in this wave, and it is the reason the wave is worth doing rather than a restyle. Nothing in the application today notices that two fixtures share DMX addresses. Auto-assign packs each universe from address 1 so its own output is always clean, but a single hand-edited address afterwards puts two moving heads on the same channel and the tool says nothing until a technician is standing in the room.

States in order of how much attention they need — overlap, then unaddressed, then clean — matching how the audio strip orders over-capacity, gaps, complete.

04 · adding

One editor replaces two dialogs

Add Fixture and Bulk Add are the same form with one field's difference. They are two separate dialogs today, holding two copies of the model picker, the mode picker and the channel count — which is why the single-add dialog quietly lacks the universe and power fields the bulk one has.

+ Fixtures opens the row editor at the foot of the sheet with a Qty field defaulting to 1. Adding one fixture and adding twelve stop being different operations, and the editor you add with is the editor you edit with — which is the pattern's own rule.

05 · the drawer

Where the universes are, and where auto-assign belongs

A universe is declared once and referenced by every fixture in it — which is the definition of a drawer, not a card stacked above the table. It is also the only place an “universe 2 exceeds 512 channels” error can be explained rather than merely reported, so Auto-assign DMX moves in here and stops being a fourth button competing with the primary action in the bar.

With that move the bar is exactly the canonical order with no exceptions: title, search, drawer, flex-1, print, one primary action.

06 · the ledger

Every column, accounted for

Thirteen columns become nine. Nothing is lost — three move into the editor, one is deleted as a duplicate of another, and one becomes readable for the first time.

# Deleted.gone A count of the rows above it, not data about a fixture. The rig's order is Order in the editor; the number a technician says out loud is the FID.
FID Leads the sheet, as a numeric cell.column Duplicates stay flagged, in amber, never blocking — renumbering a rig legitimately passes through duplicate states.
Fixture Name One cell, two facts.column The name you gave it in white, the catalog model beside it in mono — model names are equipment identifiers, which is one of the four things mono is for.
Truss Stays, still read-only.column It is derived from the stage plot. The editor gains a Hang in plot → hand-off, the same gesture the audio row editor uses for Edit in Flow →.
Position Into the editor, renamed Order.column gone It is the sort key of the sheet you are looking at; a column showing you the order of the thing already in that order earns nothing.
Power
Power Connector One column.merged grid schuko, or chain ← 101 with the link mark. Both are edited in the editor. The chain parent finally names the fixture it points at instead of printing a database id.
DMX Univ
DMX Addr
Channels Three numeric cells that line up.columns Zero-padded addresses in tabular figures, so a column of them is a column. This is where the density pays for itself: an address clash is visible as a shape before you read a digit.
Mode Text, not a select-plus-input.column The catalog-mode picker and the free-text override both move into the editor, where picking a mode still copies its channel count onto the fixture.
DMX Chain Deleted.gone It prints dmx_chain_parent_id — a raw row id, meaningful to nobody, editable nowhere. Nothing in the application writes it. If DMX chaining is real planning data it deserves the treatment power chains get, and that is a slice of its own, not a column.
Notes Stays, truncated.column Full text in the editor.
Delete Into the editor.column gone A destructive control in every row of two hundred is a mis-click waiting to happen; it belongs beside Save, held apart from it.
— new — The status strip.new Overlaps, unaddressed fixtures, duplicate IDs, and per-universe fill. None of this is computed anywhere today.
— new — Search.new By FID, name, model, mode, truss or note — as both audio tabs have.
07 · scope

What this wave does not touch

Mobile is unchanged. The phone view is already a list and a per-fixture edit sheet, which is the right shape; it uses navigation-tier sizing and keeps it.

Print is unchanged. The lighting rig sheet is a separate visual language and stays black-on-white at 9 pt.

No schema change. Every value drawn above already exists on the fixture. Overlap and universe fill are derived in the browser from data already fetched — the same shape as patchCapacity, and testable without rendering anything.

One backend question, deferred: auto-assign currently fails the whole rig if any universe would exceed 512. The drawer makes that legible for the first time. Changing the endpoint's behaviour is not in this wave.

08 · to approve

Four calls I would like confirmed

1 · Deleting the DMX Chain column

It shows a raw parent id and nothing writes it. I am proposing it goes, and that DMX chaining is either a later slice or nothing. Say if it is planning data you actually use and I will design it properly instead.

2 · Merging Add Fixture and Bulk Add into one editor

One form with Qty, defaulting to 1, at the foot of the sheet. This removes two dialogs and one duplicated model picker. The alternative is keeping the dialogs and only restyling them.

3 · The Universes drawer, and auto-assign moving into it

This is the biggest workflow change: a button that is in the toolbar today moves one click away. In exchange the bar keeps its canonical shape and the 512-channel limit becomes something you can see before you hit it rather than an error afterwards.

4 · Overlap detection as an alert, never a block

Two fixtures sharing addresses is flagged red in the cell and counted in the strip, but saving is never prevented — the same treatment duplicate FIDs already get, because a rig legitimately passes through a broken state while it is being renumbered.
