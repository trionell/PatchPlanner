OpenSpec change · console-showfile-export · Slice 49 · revision 4 · for approval

The patch already knows what the desk needs to be told

Every channel name, tape colour, stereo pair, mix, route, DCA, recorder track and 48 V flag on the Audio inputs, Desk routing and Audio outputs tabs is typed into the desk again at load-in, by hand, from a printout. Export to console writes them into a file the desk loads instead. The desk's model decides which file: an X32 / M32 scene or an LV1 session. It asks for the one thing PatchPlanner does not record, which desk socket each stagebox is plugged into, in both directions, then lists everything the desk cannot hold before you download.

Changes in revision 4 · rebuilt on the approved Slices 47 and 48
  1. No format picker. The desk's model decides the file: every X32 and M32 model writes a .scn, every LV1 model an .emo for LV1 17.3. A Generic desk writes nothing, and the dialog says to pick a model in Rig. The format rows became a statement (§03).
  2. The desk is the selector's. The Console field is gone. The dialog exports the desk selected on the sheet (B6) and, on a two-desk event, says which and how to export the other (§02).
  3. §05 is replaced. Revision 2–3's rule that put outputs on buses by their type is gone. Mixes now have slots, names, widths, colours and routes on Desk Routing, and outputs have Fed by. The export copies them one to one, and the preview reports only what the desk cannot take, in A3/B1's words (§05, §06). The folded bus list went with it.
  4. Ports as before. X32 · M32 is always written as user in / user out, so any patch exports as drawn. That costs the dialog nothing and is stated once, in §04.
  5. The recorder is written: the X32 card and the LV1 SoundGrid recorder, track by track. A sixth figure counts tracks that record and play back, and the info note says how (§06). Aux inputs are written as /auxin/NN on X32.
  6. Data: Julkonsert is now Slice 48's (FOH on an M32 Live, Monitor on an LV1 64). Söndagsgudstjänst is a desk just switched from LV1 32 to X32 Producer, to carry every red line. The wedding (Generic) is new. Drawings lose the Buses button and the phone's Groups & DCAs row, which Slice 48 deleted.

03 · the desk and its file · live in §02 · rewritten in revision 4

The model already says which file the desk loads, so the dialog states it and never asks

Revision 1 asked for the format in two rows, remembered per viewer, and refused to guess it from the catalog item. Slice 47 gave every desk a model, chosen deliberately in Rig, and a model is a fact rather than a guess. Asking again in the export would be a second answer to a question already answered, and the two could disagree: an M32R desk exported as an LV1 session. So the format rows are gone. In their place is one statement: the desk, its model, and the file and version that model gets.

It is not a control. A value derived from something declared is shown read-only and never offered as a field: that is B3's reasoning, applied to a file type instead of a count. The statement uses the note-box surface the figures already use, with no border colour and no edge, so nothing about it says press me.

04 · the ports · live in §02 · changed in revisions 2 and 4

PatchPlanner knows which box feeds a channel; only the night knows which socket the box is in

The input graph runs source → stagebox port → channel. A desk's input patch needs one more hop, stagebox → desk socket (AES50-A, AES50-B, the card, the local jacks), and no row stores it. The same S16 can be on AES50-A this week and B next week. So the dialog asks: one row per stagebox that feeds a channel or carries an output on this console, with its name, model, input and output counts and how many channels and outputs use it, and the pickers beside it.

A row covers both directions. The output graph runs output → stagebox output port or local out → amp, and the same missing hop applies on the way out. On X32 · M32 a row has up to two pickers: In for the input range, Out for the output range. A digital box's outputs ride the same cable as its inputs, so once In names a socket, Out only offers ranges on that socket. Changing In to another socket clears an Out that no longer matches. A box that only carries outputs (Monitorrack on the monitor desk) has an Out picker alone, which offers every socket.

48 V rides on this answer. On an X32 phantom power belongs to a preamp, not a channel. Writing 48 V on OH L means switching it on at whichever preamp OH L arrives through, so an unknown port means no 48 V in the file. On LV1, 48 V lives on the I/O device, in a format that differs by model. So an LV1 row picks a slot and a device model, and the export writes the device itself into the session, because LV1 does not create a device for a patched empty slot. The phantom figure in the preview counts only the channels whose preamp is known, and says so when that is fewer than the sheet's.

local jacks
On X32 · M32 the console's own jacks are one fixed row, both directions in mono with no control: Console local · 14 channels · 6 outputs → In 1–32 · Out 1–16. They map to themselves; the local outs are /outputs/main/NN, as many as the model has. The row shows only the directions in use and is hidden when neither is. Aux inputs have no row: their source is the desk's own aux jacks and USB, as the sheet says. On an LV1 Classic the console's own I/O takes a slot and a device like any other row; the LV1 software models have no jacks, so they have no local row.
no double booking
A range that overlaps another row's choice in the same direction, or the local jacks in use, is a disabled option labelled with whoever holds it (In · AES50-A 1–8 · Scen). Inputs and outputs do not collide: Scen's inputs and Monitorrack's outputs can both start at AES50-B 1. On LV1 a slot holds one device, so a slot another row has is disabled.
the first time
X32 · M32: In · not connected and Out · not connected, in placeholder ink, and an amber line in the preview saying what that costs ("Monitorrack has no port. Its 3 outputs are written with no output patch."). The dialog never guesses a port. A guessed AES50-A is wrong half the time, and when it is wrong, phantom lands on the wrong preamps. LV1: the slot starts Not connected, and the device starts as the stagebox's own recorded model when that is a model on the list, otherwise Other / not listed. The Console local row of an LV1 Classic desk starts as LV1 Classic, read from the desk's model rev 4 (revision 3 read it from the catalog item). A recorded model is a fact, not a guess.
remembered
Per event × desk × engine, per viewer, in the browser's localStorage, the slot, the device model and both ranges together. The engine replaces revision 3's format in the key: a desk switched from LV1 to X32 and back finds its LV1 slots again. The port map describes how this technician cabled this desk on this night. It is not a property of the plan, so a viewer can set it without being able to edit the event, and two technicians on one event do not overwrite each other.
what is not a row
A stage multi has no row. It is passive copper that ends at the desk's local jacks, so what it carries arrives on the fixed local row. A stagebox that feeds no channel and carries no output on this console has no row either. A row shows a picker only for a direction it uses: Scen on the monitor desk feeds channels and carries nothing out, so it has In only.
05 · what desk routing hands over · live in §02 · replaced in revision 4

Every mix already has its slot on Desk Routing, so the export copies it and reports only what the desk refuses

Revisions 2 and 3 put outputs on desk buses by their type, because nothing else said which mix fed an output. Slice 48 says it now. A desk owns its mixes, each in a slot of the model's pool with a name, a width and a colour. Routes say what feeds each one, and every output has a Fed by. The pools were already checked when the mixes were made, so the writer allocates nothing. Bus 5–6 on Desk Routing is /bus/05–06 in the scene, and Mon 6 is Mon 6 in the session. The dialog shows no assignment list because Desk Routing already is that list.

06 · the preview · live in §02 · changed in revisions 2 and 4

Every loss is stated before the download, by the code that will cause it

The dialog asks the server for a preview each time an answer changes, and the server returns two things: figures for what the file will hold, and warnings for what it cannot hold. The client computes neither. The writer is the only code that knows an X32 name is 12 characters, and a second copy of that rule in TypeScript would drift (P6: a meaning is derived in one place). While a preview is in flight the figures read Checking …, per patterns.md §5. If it fails, the inline error block replaces them and the primary is disabled, since there is nothing yet to agree to.

The figures are Channel strips · Mixes · DCAs · mutes · 48 V · Outputs patched · Recorder, in mono, three to a row at both widths, with of N after any figure the desk cut down. rev 4 On X32 · M32 the strips figure adds the aux inputs (30 +4 aux). Mixes counts what Desk Routing holds for this desk, mains apart. Recorder reads record · play tracks and its label says which recorder: Card or SoundGrid. The info note says how each is routed. Revision 3's Stereo links figure is gone, because Slice 47's hard block means a real model holds no pair it cannot link. 48 V draws the phantom bar: P5 says it is a bar in every view that shows it, and this is one.

why red, why amber
Red means over capacity (tokens.md §5), and Left out is exactly that: the plan is bigger than the desk. Everything else is something the desk shows differently, which is the gaps state's amber. Each line leads with its word so neither hue carries the meaning alone (P4). The box takes the alert tint of its worst line, rule and ground both, so the state shows at the edge of vision.
named, then counted
Each line names what it touches, up to the names that fit; past that it counts (… and 1 more). "3 names shortened" on its own would send you to the sheet to hunt for them.
colours, by value
The writer maps a channel_colors hex value to the nearest desk colour by hue, never a colour name. A user-added colour still lands somewhere (Principle II). Purple → Magenta and Grey → White inverted are one-to-one, so they do not warn. Only a merge warns, because a merge is when the desk can no longer tell apart two channels the plan could. LV1's palette has 32 colours, so none of the nine merges there; the check runs anyway.
nothing lost
One quiet line in place of the box: Nothing is left out or changed. No emerald. Emerald is the status pill's alone. In this revision's data no desk is quite clean: Monitor is clean once Scen A's device is chosen.
what else is in the file
An InfoNote on the section heading, open the first time and remembered after (it is read once): everything PatchPlanner does not know (gain, EQ, dynamics, send levels) is the console's default, so load the file before the soundcheck, not during it. rev 4 It gains one sentence for the recorder: on X32 the card is routed track by track; switch the desk to Play for virtual soundcheck, on LV1 each track is routed to the SoundGrid recorder and plays back into the channel's B input.
mixes and DCAs
rev 4 A file carries this desk's mixes, DCAs and mute groups, all of them. Since Slice 48 they belong to one desk, so revision 3's rule (the groups at least one of its channels belongs to) has nothing left to filter.

09 · amendments to design/ · approved with revision 1 · landed by Slice 47

Three rules this dialog needs that design/ does not yet state

The user approved A1–A3 with revision 1. Slice 47 lands them, with B1 adding Moved and Fits again to A3, in the same commit as its code, per CLAUDE.md. Revision 4 needs no new amendment. The desk statement is B3's rule (a derived value is stated, not a field), the Generic and empty states are §5's empty, actionable, and every preview line uses a word A3 already has. The first two change ui/Dialog itself and so reach ConfirmDialog, ChainCell and the four cable dialogs too.

A1 · components.md
§ui/Dialog
A Dialog takes an optional pinned footer, built like ui/Sheet's: flex-none, border-t border-zinc-800, below the body that scrolls inside max-h-[85svh]. Today a Dialog's buttons are its last child inside the scroll. With three stageboxes and five warnings that puts Download below the fold on a phone, and on a short laptop screen too. Callers without a footer are unchanged.
A2 · tokens.md §7
+ components.md §ui/Dialog
A Dialog's close target is h-11 w-11 around an h-5 w-5 icon on a phone, as the Sheet's is. The built Dialog's × is a bare glyph, about a 14 px target. That is amendment 1 broken by the control pressed to back out, which §7's own fixed-geometry table already names for the Sheet.
A3 · patterns.md §5
States
A new state row: a loss, stated before a download. Lines led by a word (Left out red for over capacity; Changed, No input, No port amber), in a note box that takes the alert tint of its worst line. One quiet sentence when there is none. Never a toast, never blocking. The export's warnings are the first instance; the PDF exports have nothing to lose, so they need none.
not proposed
rev 4 The format rows that revision 1 drew from MobilePicker's row are gone, so the question of naming that placement is gone with them. Navigation-tier contents in a Dialog are what every built Dialog already does. Stating it would be a fourth amendment, and it can wait until a Dialog is built otherwise.
10 · scope

What this deliberately does not do

no reading back
A scene or session is written, never imported. A desk's names do not flow back into the plan.
no mix settings
Gain, EQ, dynamics, send levels, pans and fader positions are not written. A route is a send switched on at 0 dB, nothing more. PatchPlanner does not hold the rest, and inventing defaults would overwrite a desk's house settings with ours.
no format choice
rev 4 The model decides. To get the other file, change the model in Rig, where the switch is previewed (Slice 47).
no Generic export
rev 4 A Generic desk has no file. It says so and points to Rig.
no other desks
No dLive, SQ, Yamaha, DiGiCo or Allen & Heath, no X32 firmware older than 4.0, and LV1 17.3 only until another template ships.
no edits in the dialog
A name that is too long is renamed on the sheet or on Desk Routing, not in the export. The dialog stays an answer, not a second editor.
no allocation
rev 4 The export never picks a slot, a bus or a pair. Desk Routing did, under the model's pool rules; the file copies it. Revision 2–3's output-type rule is withdrawn.
no P16
X32's Ultranet (P16) outputs are not patched by name. PatchPlanner's outputs leave through stageboxes and the local jacks, and those are what the file routes.
no per-channel source override
The input patch is derived from the graph plus one port per stagebox. To send a channel somewhere else, change the patch.
no push to the desk
No OSC, no network transfer. A file you carry on a USB stick.
no both-desks download

What can an X32 user-out slot take? rev 4

The template's own output routing feeds AES50 blocks from OUT1-8, OUT9-16 and P161-8, and our recollection of Maillot's user-routing table is that a user-out slot takes inputs, OUT 1–16, P16 1–16, aux and monitor, not a bus directly. If so, a mix reaches an AES50 or card socket through an OUT or P16 signal, and a desk carries at most 32 mix-fed signals to stageboxes (local outs are direct). Slice 47 ruled no output cap. Drawn: no cap, and no specimen reaches 32. If the table says otherwise, a Left out past 32 joins §06. To be checked against Maillot pp. 131–138 before the proposal.

A route's send level rev 4

A route is membership only. Drawn: a send switched on at 0 dB on both desks, which is what the LV1 research already wrote. On X32 a send left at the template's −∞ would make every monitor mix silent. Unity is loud on a 16-member IEM mix; the alternative is on at −∞, which is visible but useless.

No reference session holds a SoundGrid recorder, so the device row and its routes are inferred from how I/O devices and B inputs are written. Drawn as exported per track. Needs one hand-made 17.3 session with a driver and two tracks before the writer is built.
