PatchPlanner · frontend · design language

The patch surface,
as the whole application

Slices 23–26 built a deliberate visual language for the audio Inputs and Outputs tabs while the other seven tabs kept the one they were born with. This page shows what that language is, so it can be reviewed by looking rather than by reading class strings.

Every specimen below is drawn at the application's real 14 px base using shipped values — not the original mockup's scaled-down 11 px thumbnail, whose pixel numbers were never meant to be copied. Where a specimen and the code disagree, the code is right and this page has a bug.

One · the rules principles.md

Nine rules, stated so they can be broken

Each one names its own violation, because a principle you cannot fail is a slogan. They are ordered: when two pull against each other, correctness of meaning beats legibility beats reach beats consistency beats compactness.

P1 · One surface, one frame

A screen is one bordered thing holding a bar, its content, and a strip that closes it — not a stack of rounded cards separated by gaps. A gap says these are separate. Use it only when they are.

P2 · Density is a property of the surface's job

Decided by a question about the user, not about taste: does the user scan many rows of this at once? Yes is a work surface; no is a navigation surface.

P3 · One label style per tier

Mono, uppercase, wide-tracked, quiet — and its size fixed by the tier, not by the component. Currently broken inside the reference surface itself: four definitions, two sizes.

P4 · Amber is focus and action

And never the only carrier of meaning. When amber also has to say warning, it does so alongside a shape or a word. A state distinguishable from its neighbour only by being amber is a violation.

P5 · Shape carries meaning independently of colour

Every circle on the canvas is a port you can patch — so 48 V phantom power is a bar, red and glowing, in every view that shows it. It survives greyscale, a colour-blind reader, and a channel whose tape happens to be red.

P6 · A meaningful colour is derived, never typed

A colour that carries information is computed by walking the domain graph. The canvas, the sheet's Chain column and the inspector's note read the same derivation — which is why they cannot disagree, rather than being kept in step.

P7 · Restricted roles lose controls

They never gain disabled ones. A disabled control is a promise the interface cannot keep — and reading the patch is never restricted, so the surface must not read as a locked copy of someone else's.

P8 · Chrome recedes

The panel is the subject. No navigation element may be louder than the content title beneath it.

P9 · The phone is the same application at arm's length

Nothing is read-only because of a width — P7's rule about roles, restated for viewports. Drawing is not targeting: a 7 px port dot may be drawn on a phone, it just may not be the thing you hit. And what genuinely has no phone form says so, rather than rendering fewer facts quietly. Drawn in §8.

Bar order is fixed: title · view · search · drawers · extras · flex-1 · print · one primary action

The bar

  • The title repeats the tab name above it, deliberately — it anchors a panel that now has a top edge of its own.
  • The view toggle is a segmented control in a trough. Page-level tabs get no trough; an in-panel toggle does.
  • The primary action is last, and is the only filled button on the surface.

The editor

  • Nothing in a row is a form control until the row is clicked. A cell that is permanently an input turns a scannable list into a form.
  • The open row loses its bottom border and takes bg-amber-500/[0.04], so row and editor read as one block.
  • The same construction adds a row, which is what makes adding and editing look like one operation.

The strip

  • Closes the panel from inside, top border only — the alert reads from the frame's edge, not from a badge in a second box.
  • Ground and border take the tint, so a patch with gaps is visible from the edge of vision.
  • Over capacity is unreachable until an event declares a console. Inventing a capacity is worse than saying nothing.

The meter draws nothing at zero

A capacity of 0 means nobody has said yet. It renders —, draws no meter, and must never warn. That is a different state from empty, and conflating them is how a desk nobody has measured appears to be over capacity.

No control appears before Edit

A gear card's summary line has a name, an item and actions — never a field. Fields exist only once Edit is pressed, and then it is the same construction used to add. The footer states what the contents mean, not the count twice over.

Now — 16 / 18 / 14, sidebar is the ground

The tab strip lost its trough, and that is the substantive change rather than the padding. A trough belongs to an in-panel toggle selecting how you look at one thing; page-level tabs select what you are looking at. Two controls that looked identical meant those two different things. The sidebar's active marker stays a 2 px left edge and never becomes a filled pill — that keeps the amber fill meaning "the primary action" rather than "the page you are on".

The header's height is now h-14, stated rather than emerging from a padding plus a font size. Stage Plots' sticky toolbar had hard-coded top-[73px] — the number that sum happened to produce — so a height a child positions against has to be a value someone chose.

Eight · the phone principles.md P9 · tokens.md §7 · patterns.md §7

The same application, at arm's length

Not a companion app, not a viewer, not a cut-down edition — the same data, the same derivations and the same words, composed for one hand. The one thing a phone layout does not have is a column: a sheet's twelve of them, a canvas beside its rail, a drawer over the sheet it is read against are all the same move, laying two things side by side so one can be read against the other. Everything below is what replaces that move — stack it, put it behind a tap, or say it is a desk job.

These specimens are drawn at a true 375 px with the app's 14 px base, so a 44 px target is 44 px on your screen. None of it is built. components/mobile/ was written in Slice 21, two slices before this language existed, and Waves 0–5 converged the desktop around it without touching it — the distance between these drawings and the code is §9, findings M1–M12.

Density on a phone comes from stacking, never from shrinking. The tape keeps its colour and becomes the row's leading edge; the source and the routing — what a patch is — become the subtitle; the width, the 48 V and the rest of the chain wait behind the tap. What will not fit is dropped, not set smaller. Shrinking type to keep a column count is how text-[13px] and h-9 ended up in the tree, in neither tier and quoted by nothing.

What carries across unchanged

  • Every derivation. A cable's colour, a chain, a gap, a capacity — same functions, same answers, at any width (P6).
  • Shape. 48 V is a bar in the hand for the reason it is one on the desk (P5).
  • The label voice. FieldStack renders a MicroLabel on the desktop, so a sheet holding those same fields renders one too — P3 does not acquire a second answer at 767 px.
  • The verdict. If a surface has a strip on a desk it has one in a hand — the phone is where someone is standing in the room the plan describes.
  • The words. A phone that needs its own vocabulary has found a gap in the desktop's.

What changes shape

  • Columns become a title and a subtitle, ranked by what you need without opening the row.
  • The row editor, the drawer and the inspector all become one bottom sheet — ui/Sheet, which does not exist yet. Type is read, geometry is touched: what goes in keeps its tier's mono labels and 10 px specs, and gives up only h-8 and h-7 for 44 px.
  • The canvas becomes a viewport — one coordinate system, nothing pinned to an edge. Pan to the sources and the desk leaves the screen, which is the point.
  • Nine tabs become one control that names the current section, and the list carries each section's own count — the same derivations Overview's numbers band reads.
  • The sidebar becomes four bottom slots, and the active mark is colour alone — there is no left edge to put 2 px on.

What stays at the desk

  • Exactly one thing, and it is a gesture, not an object: dragging a cable from one port to another, placing a box on a scale drawing.
  • So the plot that will not let you move a riser will let you tap it and rename it, and the canvas that will not let you patch will let you change the stand the mic is on. That is a form over a row, and forms are what a phone is good at.
  • Both canvases still render. Reversing that rule is the point: the picture of where the signal goes is what a technician wants on site.
  • The withholding is a sentence in the panel, never a disabled control and never a role (P7, P9). !isMobile never appears in a permission expression.

Nine · where it stands audit.md

Twelve closed, twelve open

Counted from frontend/src — the A-findings at the merge of Slices 23–26, the M-findings at bfb62a2. Every number below is reproducible with a grep given in the audit, so this can be re-run rather than believed. Two of the A-findings are inside the reference surface itself — it is the best thing in the codebase, not a perfect one.

All five desktop waves have landed, and every A-finding is struck. The list stays as a record of what was wrong and when it stopped being wrong, not a queue that emptied. A twelfth was added by Wave 2, because converting a surface is how you discover what an audit's greps could not see — and twice the audit turned out to be wrong rather than the code: about Lighting in Wave 3, and about the inventory catalog in Wave 5.

Four are closed and eight are open, and all twelve are the phone. Wave 6a took M8 with M7, M10 and M12 — three of which this table had left unassigned, and all three of which lived inside the six files 6a was already rewriting. A finding with no phase is a finding nobody has agreed to close. They are one finding wearing twelve names, and the name is a date: components/mobile/ was built in Slice 21, two slices before this language existed, and every wave since converged the desktop around it. Wave 4 says so in writing — “the phone branches, the print sheets and the whole backend are untouched” — and that was right at the time, because a wave that mixes a refactor with a redesign makes a regression unattributable. What it means now is that the phone is the last surface still speaking the language the app was born with.

M1The phone has no frameWave 6bP1

grep -rn "PatchPanel\|StatusRail" components/mobile/ → 0. Every phone surface is a heading, a search box, then rows as free-standing bordered cards on the page ground — P1's named violation, and the exact shape Waves 3–5 spent five slices removing from the desktop. The row sits on bg-zinc-900, which is the control role: the list reads as a column of inputs.

M2The row is off both ladders — and the document said otherwiseWave 6bP2 · P3

text-[13px] over text-[11px] at py-1.5, beside an h-9 search and an h-9 w-9 add button. 9 uses, none of them a value in either tier. The document was the bigger problem: §7 claimed mobile used navigation sizing throughout and that nothing mouse-sized appeared at all, while the code shipped a h-3.5 pencil on every row and a micro-label on three phone surfaces. A rule nothing obeys is not a rule, and this one had been quoted.

M3No phone surface says whether the plan holdsWave 6bP1 · P9

4 status rails exist — Patch, Lighting, Rental, Equipment. 0 render on a phone, which is where someone is standing in the room the plan describes. The rental tab has a hand-built total row in the control colour, a strip in intent, outside the component that already does this four times.

M4A viewport is &&-ed into a permissionWave 6cP7 · P9

const editable = !readOnly && !isMobile in Equipment, Rental and Stage Plots, so “this has no phone form yet” reaches the user as “you may not”. The sharper half is one line: onClick={readOnly ? undefined : …} is correct on six desktop sheets, because a desktop row already shows every column — on a phone the row is a truncation, so the identical expression means a viewer cannot read the patch at all.

M5The rig cannot be declared from a phoneWave 6cP9

All three tabs return their phone branch before the Rig, Buses and Universes drawers render. So the edit sheet's Stagebox select can only offer what a desktop session declared earlier, and a stagebox that arrives at load-in cannot be entered from the loading bay.

M6The Flow canvas never mounts on a phoneWave 6dP9

The rule both documents carried — “a patch graph on a phone is unreadable at any density” — is reversed, on the report that the picture of where the signal goes is exactly what is wanted on site. The canvas is drawn as it is drawn and only the editing gesture is withheld. Stage Plots already does the viewable half and is the working precedent.

M7A phone-only vocabulary, in a reserved hueWave 6aP3 · P4 · P9

The section switcher graded all nine sections editable / read-only / viewer — three words the application does not otherwise use, describing the state of the build rather than the show, telling a viewer-role user that Audio Inputs is “Editable”. Riding along: sky, which tokens §5 reserves for the legend stroke; a sixth micro-label definition, written as font-bold tracking-wide so neither the A1 nor the A12 grep would have found it; and a trigger that was amber whether or not anything was selected. → All of it deleted, nothing put in its place, and the current section marked by the sidebar's own 2 px left edge in the open list. Its type comment had said the badge “never overrides a user's actual role-based permission”: a field whose comment says it may not be believed is a field with no reader.

M8The phone's sheet is a centred dialogWave 6aPatterns §7d

5 call sites used ui/Dialog — max-w-2xl, centred, no Escape and no internal scroll, where ui/Drawer had both. A long form could not be scrolled to its confirm, and the confirm sat where the keyboard opens. → ui/Sheet, and ui/Dialog gains both by addition while staying centred at every width. ui/Drawer anchors itself, so six drawers acquired a phone form from four lines in one component without one of their own files being touched.

M9Two tabs have no phone branch at allWave 6cP9

Overview and Settings render their desktop markup at 375 px. Overview is the worse and the more interesting: it is Wave 4's best surface, and its numbers band is five text-[26px] figures in a row while its ribbon is the flow canvas one row high. On a phone the band wraps and the ribbon overflows — yet those five figures are the right five facts for someone on site. It needs a phone form, not an exemption.

M10The body's bottom padding is a guessWave 6aA5, again

pb-20 cleared a bar whose height was a padding plus an icon plus a font size, plus a safe-area inset that varies by device. And the inset was always 0: index.html had no viewport-fit=cover, so both call sites had been inert on the device they were written for since Slice 21 — invisible in a desktop browser at 375 px, which is why five waves of review missed it. → The meta tag, a stated h-14 on the nav, and a body padding derived from it. Fixing the tag is what turned the rest from dormant into urgent.

Convergence order

No wave mixes a refactor with a redesign, so a visual regression is always attributable to the wave that caused it — the reasoning that made Slice 26 rewire the inputs inspector onto the shared rail before building the output one.

Wave 0 ✓Primitive gapsA1–A3, A11 and half of A9. Visible delta, in full: 10 drawer buttons gain 1 px of padding a side, Stage Plot's two inspector buttons rise to h-7, drawer labels grow 1 px. Everything else byte-identical.
Wave 1 ✓ChromeA5, and A4 where it touched chrome. Smallest diff, largest perceived change, and it changed no tab — only the two files that had hard-coded the chrome's dimensions.
Wave 2 ✓Stage plotsA10, A12. The panel pattern transferred to a canvas that is neither a sheet nor a list, and PatchPanel needed no change — but the zoom control, the inspector rail and Tab each did, which is why this wave came before four more tabs depend on them.
Wave 3 ✓LightingA8, and A6–A7 on this surface. The restyle was the smaller half: the rig had no DMX map at all, so nothing had ever noticed two fixtures sharing addresses. Sharing turned out to be legitimate — twenty pars on one address is how a room wash is rigged — which the audit had not considered, and which restructured the whole finding. Only RowEditor changed in ui/-adjacent code, by addition; the backend ended smaller.
Wave 4 ✓The remaining event tabsRental, Equipment and Signal Flow were the conversion the audit predicted. Overview was not. Filed as “a form that needs the navigation tier applied consistently”, it became the screen that says what the whole event amounts to — five figures at 26 px, the rig drawn as the flow canvas one row high, and every panel's own verdict in one line. It also found that RowEditor's hand-off had never rendered: the desktop tab strip was uncontrolled, so no tab could open another.
Wave 5 ✓Pages and residueThe audit's second miss: the 308-item inventory catalog, filed under pages. Categories became a filter column doing one job — they used to show four of twenty-seven, because each tile also carried a rename, a delete and a picker-role select. The dashboard was rebuilt rather than trimmed and lost cards entirely. The signed-out start page is exempt, in writing, rather than half-converted.

Two primitives first — ui/Sheet (6a) and MobilePanel (6b) — then the nine surfaces (6c), then the canvases (6d), which are last because they are the only phase that adds a capability rather than converting one. 6a is done (Slice 33): ui/Sheet, Drawer anchoring itself so six drawers got a phone form from one branch, and Dialog gaining Escape and internal scroll by addition. Reviewing this

This page renders design/*.md and adds nothing to them. If a value here looks wrong, the fix belongs in design/tokens.md or design/components.md and then here — never here alone. The source of this page is design/design-language.html, beside the documents it draws, so it can be revised and republished to the same URL.

What is not settled and worth an opinion: whether the two rig operations Wave 3 added should be undoable, and whether a hand-off should carry the row as well as the tab — today it opens the right screen and finding the row there is still yours. The navigation tier's table is settled: six surfaces left it, and what remains uses it correctly. So is the start page — it is outside this language on purpose, and the one thing that came out of it is the pulse now travelling the dashboard's ribbon.

On the phone, one question is open and it is a field question rather than a document one: whether a canvas in the hand wants the desktop's pan-and-zoom, or a fit-to-width default with zoom as the exception. Nobody has held a 60-channel patch graph on a phone yet. §8 draws the pan-and-zoom answer because it is the one the desktop already has — which is a reason to start there, not a reason to be right.
